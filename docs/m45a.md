## How it works

### Packs (`packs/<id>/`)

`pack.yaml` is the manifest; the router validates it, naming the field on any error.
- `source` is an exact package and version, never `latest` or a range.
- Names that look alike are listed in `lookalikes`.
- `scope: [project]`.
- Commands are argv lists whose only placeholders are `{tool_id}` and `{tool_ids}`.
- `owned` and `artifacts` are path globs inside the project.

`pack.lock.json` is generated by `python3 scripts/pack-lock.py <id>` and committed. It holds:
- every file's URL and hash, transitive dependencies included
- for PyPI: the wheels for Python 3.11–3.14 on Linux x86_64/aarch64 and macOS arm64/x86_64, plus a pinned pip
- the manifest fields hostprobe needs

hostprobe only ever reads the lock. The router refuses a lock that no longer matches its manifest ("…lock doesn't match its manifest (python3 scripts/pack-lock.py <id>)"); `--check` tests that.

Shipped:
- OpenSpec 2.1.1 (`@fission-ai/openspec`, 66 packages)
- graphify 0.9.115 (`graphifyy`, 31 wheels per target; 16 targets)
- gstack, refused because it is global-only

### Installing (hostprobe, `services/hostprobe/packs.py`)

1. **Download** only the lock's URLs: https, from `registry.npmjs.org` or `files.pythonhosted.org`.
   - Each file's hash is checked first.
   - Then the **name and version written inside** it (`package.json`, the wheel's `METADATA`) must equal the lock's. A swapped file or a typosquat fails here and nothing is installed.
2. **Install offline**, inside `unshare --map-current-user --net` (same user, no network) on this machine:
   - npm: `npm ci --offline --ignore-scripts` from the downloaded tarballs. npm still checks each integrity hash. Install scripts never run.
   - PyPI: `python3 -m venv --without-pip`, then the pinned pip wheel installs `--no-index --require-hashes --only-binary :all:`.
   - No `uv`, `pipx` or `python3-venv`, and so no sudo, is needed.
   - On a machine without user namespaces the plan says so, and the install still uses only the checked files.
3. Python files are **compiled before** anything is recorded.
4. **Wrappers** are written: `<version>/sbbin/openspec`, `<version>/sbbin/graphify`.
5. `store.manifest.json` records every file's sha256 and a tree hash; then the version folder is made **read-only**.
6. `detect` runs (`openspec --version`, `graphify --version`).
7. The `current` pointer moves. The previous version is kept; older ones are pruned.

One install runs at a time. Plans are single-use. hostprobe never runs as root, and a `sudo` shim fails any sudo call. The environment is built fresh, with no Switchboard secrets. Each action is a `pack_installs` row (Recent installs).

### Per job (hostprobe setup task, polled by the job loop)

**Before every use** the version folder is re-hashed against its manifest.
- A changed, missing or extra file refuses that pack for this job: "graphify 0.9.115 changed on disk since it was installed — reinstall it in Connections → Packs".
- A plain job goes on without the pack. A workflow job fails with that reason.

**Setup.** The lock's commands run in the worktree through the wrappers, without network and with a timeout:
- `openspec init --tools <agent> --scope project`
- for graphify: `graphify extract . --code-only`, `graphify cluster-only . --no-label --no-viz`, then `graphify install --project --platform <agent>`

**Wrappers.** A wrapper finds the job's worktree by its `.switchboard/packs.json` marker, which must be under the worktree root; anywhere else it refuses. It sets `HOME` and `XDG_CONFIG_HOME`/`XDG_DATA_HOME`/`XDG_CACHE_HOME` to `<worktree>/.switchboard/home`, plus the pack's own settings (telemetry off, no update check, `GRAPHIFY_BACKEND=none`) and `PYTHONDONTWRITEBYTECODE=1`. So OpenSpec's `~/.local/share/openspec` and telemetry id, and graphify's `~/.cache/graphify`, land in the git-ignored `.switchboard/`. That holds whether hostprobe runs the tool or the agent does: the job's run PATH starts with the wrappers.

**Sorting every write.** A `git status` snapshot with hashes is taken before and after:
- **Owned**: the exact files the setup wrote inside the manifest's `owned` globs, plus new folders like `graphify-out/`. These are never committed; diff and commit exclude them by literal path. Your project's own tracked `.claude/skills/*` stay committable.
- **Artifacts** (`openspec/`): reviewed and committed with the code.
- **Setup edits**: anything else. graphify's project install appends a section to the tracked `AGENTS.md` and creates `.claude/settings.json`; its docs don't mention the `AGENTS.md` edit. The exact patch is kept (zero context, so only the setup's own lines count). The edit is shown unticked; an unticked one is reverse-applied to the index only at commit.
- A link pointing outside the worktree rolls the setup back.

**Agent instructions.** The task text names the skill and its file (`.agents/skills/openspec-propose/SKILL.md`). This matters because Claude Code jobs run with `--setting-sources user` (M4a: a repository's own `.claude/settings.json` hooks never run), so project skills may not be offered to it. The pack's commands (`openspec`, `graphify query`, …) are added to what the agent may run.

### graphify (ADR 0019)

- **When:** Auto uses it when the project has at least 1,500 tracked files or 20 MB (`config/packs.yaml`). Always uses it on every agent job, and Off never does.
- **Graph cache:** the graph is refreshed from a per-project copy in `~/.switchboard/data/packs/graphify/<project>/`, copied in before and back after.
- **Measuring:** jobs are grouped by project + agent + workflow. Every 5th eligible job runs without the graph until each side has 5 finished jobs.
  - Median tokens (input + **cached input** + output) at least 10% lower → **on**, holdouts stop.
  - Otherwise **off**, with the numbers.
  - After 20 more eligible jobs a new round starts: 5 control jobs when on, 5 graph jobs when off.
- **Cached input** is now recorded: `costs.tokens_cached`, from Claude's `cachedInputTokens`, Codex's `cached_input_tokens` (Codex counts it inside input, so it is taken out) and OpenCode's cache read/write. Metrics' input tokens include it, so there is one definition everywhere. Older rows have none, and the panel says so.

  - It needs Node ≥ 22.20 (SPEC said 20.19).
  - The commands are skills now: `openspec-propose`, `openspec-apply-change`, `openspec-archive-change`. Codex uses `$…`.
  - `--scope project` writes `.agents/skills/openspec-*`, `.agents/skills/.openspec-target`, relative links in `.claude/skills/`, and `openspec/`. It edits no tracked file. It writes `~/.local/share/openspec/projects.json`, redirected by the wrapper.

  - On PyPI it is `graphifyy`; `graphify` returns 404.
  - `--project --platform claude` writes `.claude/skills/graphify/**` and `.claude/settings.json`, and edits `AGENTS.md`. `--platform codex` writes `.codex/skills/graphify/**` and `.codex/hooks.json`, and edits `AGENTS.md`.

- **npm offline installs:** `npm cache add` + `--offline` does not work (the cache is keyed by URL). `resolved: file:<checked tarball>` does, and npm still verifies integrity.

## Decisions taken without asking (reversible)

- **The gate between steps is a new `step` gate.** "Approve and go on" starts the next step; the last step goes to the usual diff review.
- **Workflows are lazy (SPEC §8a.6).** A project's packs are only offered; a job sets up a pack only when its workflow uses it, or when the graph decision says so.
- **Graph and caches:**
  - graphify's per-project graph cache lives in Switchboard's data folder (`~/.switchboard/data/packs/`), next to attachments.
  - graphify's hooks file (`.claude/settings.json`), when the project doesn't track one, counts as pack-owned.
- **Metrics counts cached input in input tokens.** That makes Metrics and the graphify panel one definition, as you asked; costs in dollars are unchanged.
- **Spec Kit is not shipped.** `specify init` downloads templates during setup, which the no-network setup refuses; it waits for M4.5b.
