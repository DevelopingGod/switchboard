# M0 — Infrastructure

Postgres + LiteLLM in Docker, Ollama on Windows, Paperclip native in WSL.

| Component | Where | URL |
|---|---|---|
| Postgres 17 (`switchboard`, `litellm` DBs) | Docker | `127.0.0.1:5432` |
| LiteLLM proxy | Docker | `http://127.0.0.1:4000` |
| Ollama (`qwen3:4b`) | Windows | `http://host.docker.internal:11434` (from Docker) |
| Paperclip (embedded Postgres, systemd user service) | WSL | `http://127.0.0.1:3100` |

## Setup

Prerequisites: WSL2 Ubuntu with systemd, Docker Desktop (WSL backend), Ollama running on Windows with `qwen3:4b` pulled.

```bash
scripts/setup-wsl.sh
```

This installs nvm + Node 24 (Linux), creates `deploy/.env` with generated secrets, starts Postgres and LiteLLM, checks Ollama, and onboards Paperclip as a loopback-only background service.

Then add `GROQ_API_KEY` and `GEMINI_API_KEY` to `deploy/.env` and recreate LiteLLM:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d litellm
```

## Check

```bash
scripts/doctor.sh
```

Green/red = M0 components (non-zero exit on red). Yellow = later milestones (agent CLIs, Cerebras, Arch-Router) or a fallback was used.

Manual call:

```bash
set -a; . deploy/.env; set +a
curl -s localhost:4000/v1/chat/completions -H "Authorization: Bearer $LITELLM_MASTER_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"ping"}]}'
```

## Model aliases (`config/litellm.yaml`)

| Alias | Model | Fallback |
|---|---|---|
| `fast` | Groq `openai/gpt-oss-120b` | `smart-free` |
| `smart-free` | Gemini `gemini-3.5-flash` (pinned) | — |
| `local`, `private` | Ollama `qwen3:4b` | none (never leaves the machine) |

## Operations

```bash
paperclipai service status    # ~/.local/bin/paperclipai, pinned 2026.1106.0
paperclipai service logs
docker compose --env-file deploy/.env -f deploy/docker-compose.yml logs -f litellm
```

## Notes

- WSL uses NAT networking, so Ollama is not reachable from WSL `localhost`; LiteLLM reaches it via Docker Desktop's `host.docker.internal`. `doctor.sh` checks from inside the LiteLLM container for that reason.
- The `claude`, `codex` and `gemini` on PATH are Windows binaries. Paperclip drives CLIs on its own host (WSL), so Linux installs are needed in M1.
- `LITELLM_SALT_KEY` encrypts provider keys stored in the LiteLLM DB; never change it after first start.
