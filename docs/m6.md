Branch `m6`. Decisions: [ADR 0011](adr/0011-metrics-charts-hand-rolled-svg.md) (charts) and
[ADR 0012](adr/0012-metrics-rollups-and-litellm-dedupe.md) (one costs table, LiteLLM call ids, 15-minute rollups).
The plan was approved on 2026-11-21 with your choices: 15-minute buckets (not hourly, so +5:30 and +5:45 offsets are
exact), the browser's time zone for day boundaries, the Agents Dial as month vs monthly cap, and two additions
(honest savings with Settings → Subscriptions; titles only in per-request views).

## What you can do now

| Where | What |
|---|---|
| `/metrics` (Simple) | **Today / 7 days / 30 days** in your own time zone (remembered in a cookie). Five numbers: **Spent** (real money, what counts toward caps), **Value at API prices** (what everything would cost at list price, including free and subscription use), **Net saved** (value − subscription fees for the range − spent), **Requests** (chats, errors) and **Jobs done** (failed). Up to four one-line insights, a note when demo requests are left out, and a spend-and-value chart with **Show as table** and **Export CSV**. |
| `/metrics` (Pro) | Everything above, plus: **Breakdown** by provider, model, agent, rule, intent, project or kind (requests, errors, 429s, timeouts, fallbacks, p50/p95, tokens, spent, value; jobs done/failed/success for agents and projects; **Load more**); **Errors and fallbacks** and **Response time** charts; **Free quotas** (today vs each provider's limit, with reset times, from the counters routing uses); **Budgets** (chat daily cap and each agent's day and month, with "at this rate you'll reach it at 18:00", or **No cap**); **Feedback by model** (👍/👎); **Jobs by agent**; **Most valuable requests** (thread titles and job names only); **Include demo traffic**. Every table exports CSV. |
| Settings → Subscriptions | Plans you pay for: name, monthly fee, since, until (optional). Used only for net savings. |
| `/jobs/agents` | The budget Dial is this month's list price against the agent's monthly budget, and says **No cap** (never a percentage) when there is none. Today's spend is in the text beside it. |
| Footer | "Value saved" is now **Free value**: it is the list price of today's free calls, not savings after fees. |

## How it works

### One table, counted once

Three sources write to `costs`, each with a unique `external_id`:

| Source | Written by | `external_id` | `kind` |
|---|---|---|---|
| A chat turn | the router, when the reply ends | `litellm:sb-chat-<hex>` (also sent to LiteLLM as `x-litellm-call-id`) | `chat` / `media` |
| An agent run | the job engine (M4a), per Paperclip run | `paperclip-run:<run id>` | `job` (+ `job_id`) |
| Any other LiteLLM call | the spend-log ingester, every 5 min | `litellm:<call id>` | `aux` (titles, summaries), `test` (model tests), `external` (other clients) |

The ingester reads `GET /spend/logs/v2` from a saved cursor (10-minute overlap) and inserts each successful call with
`ON CONFLICT DO NOTHING`, so a call the router already recorded is skipped. Chat logs younger than 15 minutes wait
for a later run, so the router's own insert always comes first. Calls from before the first ingest without an `sb-`
id are pre-M6 chat turns (already in `costs`) and are skipped; **history from before M6 is not imported from LiteLLM.**

Demo traffic keeps its tag (`end_user` / `request_tags` = `switchboard-demo`, `requests.decision_json.tag`,
`costs.tag`, `jobs.tag`) and is left out unless you include it.

### Rollups

`metrics_15m` has one row per 15-minute bucket (UTC) and dimension set. Triggers on `costs`, `requests`, `jobs`
(insert, update and delete: the old and the new bucket) and on 👍/👎 append the bucket to `metrics_dirty`. A worker
(every 60 s, one at a time via an advisory lock) recomputes each dirty bucket from the raw rows and deletes exactly
the marks it read. Latency is kept as fixed-edge histograms, so p50/p95 for any range are merged sums, interpolated
within one bucket. Reads group buckets by the viewer's local hour or day; answers are cached 30 s.

Repair or rebuild any range: `docker compose … exec router python -m app.metrics.rollup --rebuild --since 2026-11-01`.

### Money words

- **Spent** = `cost_usd` (free tiers and local models are $0).
- **Value at API prices** = `list_price_usd` (when a source reports none, what was paid).
- **Net saved** = value − subscription fees − spent. Fees are spread per calendar month from each plan's start date
  (Claude Pro $20 from 16 Nov = $10 of November). Insights only use net saved; when it is negative they say
  "Subscriptions cost more than they saved this period". Without subscriptions they say what it would have cost and
  ask you to add them, rather than calling it savings.

### Privacy

The per-request list is built in the router's serializer, not the UI: a chat row shows its thread's title (passed
through the secret masker), a private thread shows **Private chat**, a job shows its name (masked), and other calls
say what they were ("Title or summary", "Model test", "Another LiteLLM client"). Prompts and message content are
never read by these queries. All `/metrics/*` endpoints need the admin token, like the chat API.

### Portal

- `/metrics` is a server page (reads `/metrics/summary` with the time zone cookie); range switches, Pro sections and
  paging go through `/api/metrics` (loopback Host and same-origin only, parameters whitelisted, admin token on the
  server).
- Charts are hand-rolled SVG (ADR 0011): validated colours on an opaque surface in both themes, hatch textures and
  dashes so no series depends on colour, a legend, a hover tooltip, a text summary, and the same numbers as a table.
- CSV: RFC 4180 quoting, a byte-order mark for spreadsheets, and a leading apostrophe on any text cell starting with
  `=`, `+`, `-`, `@` or a tab (a chat titled "=SUM(…)" can't run as a formula).
- Pro sections are a separate lazy chunk: Simple mode never downloads them.

## Decisions taken without asking

- **Net saved = value at API prices − fees − spent**, where "value at API prices" is the list price of *everything*.
  Your addition said to label Σ(list − cost) as value *and* subtract spend again, which would count paid calls twice
  (a $1 call at a $1 list price would show −$1 saved). Using the total list price keeps your formula and label and
  gives $0 for that call.
- **Footer "Value saved" → "Free value"**, to match the honest-savings rule.
- **Agent spend joins costs by `job_id`** instead of the job's request id (same result today; explicit).
- **`costs.kind`** column added (the plan had it derived): it keeps every query simple and is backfilled.
- **Metrics API requires the admin token** (it shows titles and job names).
- **Pre-M6 LiteLLM history is not imported** (it can't be told apart from chat turns already counted).
- Breakdown paging is offset-based over the aggregated rows (at most a few hundred per range); the per-request list
  uses keyset paging.
