# M1.5 — Design polish and self-healing

Branch `m15`. Built after M2. Screens: [docs/screens](screens/) (`chat-*`, `chat-hover-*`, `chat-why-*`, `settings-*`, `status-*`, `footer-*`, `tooltip-*`, `shortcuts-*`, `splash-*`, both themes).

## Run it

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build router   # migration 0003, sync loop
cd apps/portal && npm run dev                                                           # http://127.0.0.1:3000
scripts/doctor.sh            # never hangs now; add --verbose to see every command (secrets redacted)
```

## doctor.sh

- **Why it hung:** the Host section ran `timeout 10 bash -ic …`. An interactive bash ignores SIGTERM (what `timeout` sends) and contends for the terminal, so it never returned.
- **What changed:**
  - stdin is `/dev/null`, and no interactive shell is started.
  - Node source = the login-shell PATH, plus a check that `~/.bashrc` loads nvm.
  - Every external call has a hard limit: 5 s for commands, 3 s for network. Exceptions: 10 s for the router's CLI-detection endpoints, 45 s per live model call.
  - Docker down short-circuits the compose checks.
  - Each check is named before it runs.
- **Cerebras:** `optional: true` in `config/providers.yaml`, so it shows grey ("skipped").

## Self-healing (router)

- **Root cause of "Model with id=… not found in db":** LiteLLM v1.108.8 lists a `<provider>/*` wildcard deployment once per provider model in `/model/info`, all with one id. Reconcile treated rows 2..n as duplicates and deleted that id, which removed the wildcard; the next delete of the same id then failed. `managed_deployments()` now collapses rows by id.
- **Idempotent writes:**

  | Action | LiteLLM answer | Result |
  |---|---|---|
  | Delete a model or credential that is already gone | 400 `not found in db` or 404 | Success |
  | Create a deployment whose id already exists | 500 `Failed to add model to db` | `PATCH /model/{id}/update` |

  Deployment ids are deterministic per Switchboard key, so re-creating one is an update. One reconcile runs at a time (a lock).
- **`app/sync.py`** runs a sync:
  - on startup and every 5 min;
  - when the 10 s liveness probe sees LiteLLM come back after being down (a restart);
  - when the 30 s diff finds an expected deployment or credential missing;
  - on request (a failed registration, the Retry buttons, a chat that meets "Invalid model name").

  Failures retry with backoff, 2 → 60 s.
- **Restart detection:** LiteLLM exposes no restart marker. A restart that keeps its DB needs no repair; one that loses state is caught by the diff.
- **Plain errors:** HTTP errors are `{code, message, detail}`. The portal maps the code to one sentence and one action (`apps/portal/src/i18n/errors.ts`, `components/kit/ErrorNote.tsx`); `detail` is shown only in Pro mode.
- **Endpoints:**

  | Endpoint | What it does |
  |---|---|
  | `GET /system/components` | Status view |
  | `GET /system/sync` | Sync state |
  | `POST /system/resync` | Resync now (admin) |
  | `POST /connections/{id}/resync` | The card's "Retry now" (admin) |
  | `GET /system/summary` | Footer: health, spend, value saved, quota, version |
  | `GET/PUT /settings` | Caps and private-by-default over `rules.yaml`, stored in `system_meta` |
  | `PATCH /chat/threads/{id}` `{pinned}` | Pin a thread (Alembic `0003`) |
  | `GET /chat/export?format=json\|md` | Export chats |
  | `DELETE /chat/threads` `{"confirm":"delete all chats"}` | Clear all chats |

## Portal

| Area | What |
|---|---|
| Footer | `shell/AppFooter.tsx`, polls `/api/status` (server-side proxy of `/system/summary`) every 60 s while visible. Dots link to `/status`. Icon row on phones. |
| Status | `/status`: each component with an in-app fix (Resync models, Re-test provider, Re-check CLIs) or a plain instruction (Start Docker Desktop, Open Ollama, …). |
| Splash | CSS only (`layout.tsx` + `globals.css`, flag set by the pre-paint script): once per session, ≤ 1.2 s, `pointer-events: none`, none under reduced motion. `?nosplash` skips it. |
| Transitions | `app/template.tsx` animates client navigations only; `loading.tsx` skeletons sized like each page. `<main>` is at least one viewport tall, so the footer never moves while a page loads. |
| Shortcuts | `lib/shortcuts.ts` is the one registry for the `?` sheet and the handlers: mod+K, ?, mod+B, mod+Shift+O, /, mod+., list keys. |
| Tooltips | `lib/enhance/tooltips.ts` (delegated, loaded on idle) + `components/ui/tooltip.tsx` (`data-tip`). Radix Tooltip was tried and dropped: it put popper into every route and `/chat` over 200 KB. |
| Scrollbars | Thin, themed, auto-hiding (`globals.css` + `lib/enhance/scroll-activity.ts`). |
| Chat | Sidebar groups (`lib/thread-groups.ts`), search, row menu, pin, keyboard nav, mod+B rail, phone fold. 760 px column, sticky composer, date separators, provider line, hover actions, scroll-to-latest, stream reveal. |
| Why popover | Opens below its chip; above only inside its own reply. Otherwise a spacer (`#chat-spacer`) and a scroll make room below. Radix flipping is off. A click on the stand-in chip before the chunk loads is remembered. |
| Settings | Profile, Goals & preset (the wizard's steps), Appearance, Privacy, Budgets, Data (export via `/api/export`, clear with typed confirm), Run setup again (`/welcome?step=1&again=1`, staged until Finish). |
| Motion | Tokens in `design-tokens.ts` (tested 150–300 ms). CSS stagger, lift, page-in, block-in; the Dial is CSS now (−6.4 KB). Reduced via OS or `html[data-motion=reduce]`. |
| Cursor | `lib/enhance/cursor.ts` + `.glow-edge` / `.sb-glow` CSS; never touches `cursor`. |
| Top bar | A scrim repaints the sky behind the sticky nav, so scrolled content no longer shows between the pills. |

### CLS fixes found while measuring

- The footer started in view while a short skeleton loaded, then moved.
- The Appearance menu and `?` buttons collapsed while their chunks loaded.
- The composer's read-only note on phones appeared only after hydration.

All three fixed, and a throttled-phone CLS test was added.

## Known and open

- **Visual flakes (fixed):** under load, lazy gallery components arriving late shifted the page while an element was captured (`provider-card`, `composer`). Gallery shots now wait until the page height is stable (`settled()` in tests/helpers.ts); the full suite (187) then passed twice in a row.
- **Markdown shift:** the lazy Markdown swap still shifts `/chat` slightly (part of the 0.002).
- **JS budget headroom:** `/chat` and `/welcome` are within 3.2 KB of the 200 KB budget. Trim before adding shared code.
- **`explore` alias:** OpenRouter `openai/gpt-oss-120b:free` answered 404 through LiteLLM during live checks; the model may be retired. Not fixed here.
- **Not done:** the Home composer doesn't read the private-by-default setting yet (only `/chat` does).
