# M2 — Chat + Router (rules-based)

Chat in the portal, routed by rules. Each message is matched to a rule in `config/rules.yaml`, which sends it to a model. The answer streams back through LiteLLM. If a target is down, rate-limited, over budget or not allowed, the router moves to the next fallback and records why. Every reply carries a **"Why this?"** chip that shows the rule, model, top reasons, runner-up, skipped targets, tokens, cost and latency. The Arch-Router classifier, scoring and the Rules UI are M3.

```
 browser ──POST /api/chat/stream (same-origin, JSON)──▶ Next.js server ──admin token──▶ Router API
   ▲                                                   (passes SSE through)              │
   └──────────── SSE: start · route · fallback · thinking · delta · done · title ◀───────┤
                                                                                         ▼
                        decide (rules.yaml + preset + health + caps + private) ──▶ LiteLLM ──▶ Groq / Gemini / Ollama / …
                        log: requests · costs · model_stats · messages              (disable_fallbacks: router walks the chain)
```

## Rules (`config/rules.yaml`)

The rules are the SPEC §7.2 and §8d rules, plus four additions:

| Key | What it does |
|---|---|
| `defaults` | `temperature`, `autonomy`, `max_cost_usd` (per request), **`daily_cap_usd`** (new), **`max_context_tokens`** (history sent, newest first), `max_output_tokens`. |
| `rules` | `when` keys: `private`, `intent`, `size`, `quality`, `command`. The **most specific** match wins (most `when` keys; ties keep file order). `job: true` marks a request that suits an agent job (M4). |
| `slash` | `/chat /code /research /image /video /private /bulk` → rule id. The command is stripped from the prompt. |
| `presets` | `free` / `balanced` / `best` overlay rules and set the paid policy. The wizard's saved preset picks one (default `balanced`). |

**Pipeline** (SPEC §7.1; `services/router/app/routing/engine.py`, a pure function, unit-tested):

1. **A manual pick** (the composer's Target) wins. Slash commands are still stripped, and `/private` still applies.
2. **A slash command** selects its rule.
3. **Hard rules:** Private (the toggle, `/private`, or a thread that is already private) uses the `private` rule. Attachments are a reserved hook; there is no attach UI yet.
4. **Intent** comes from keyword heuristics (`heuristics.py`), which stay until M3. The categories are code (fences, stack traces, language words; *large* means repo, tests or over 1,500 characters), research, writing (with *high* quality for "polished", "publication-ready", …), image and video. The cue that matched is shown in the chip.
5. **Otherwise** the `default` rule applies.

**Targets.** `model:<alias>`, `model:<provider>/<model id>` (any catalog model), `best:<capability>`, `agent:<id>` and `media:<id>`.
- **`best:<capability>`:** the best connected catalog model with that tag. It prefers free, then cloud over local, then the lowest measured p50, then the largest context, and returns a runner-up. M3 replaces this with scoring.
- **Specific models** go through one `"<provider>/*"` wildcard deployment per connected provider. `reconcile.py` registers them, and LiteLLM's pattern router maps them to the provider's stored credential; this was checked live with `groq/openai/gpt-oss-20b`.
- **Agents** are skipped with "jobs arrive in M4". The chat models at the end of `code-heavy` and `research` then answer in chat, and the reply shows a disabled **Run as job (M4)** button.
- **Media** rules return a "coming in Studio (M5)" notice without calling a model.

**Presets.**
- `free`: paid providers and agents are never used, not even as a fallback.
- `balanced`: free first; paid models only when you pick them.
- `best`: `default` and `writing` start from `best:reasoning`; paid models are allowed within the caps.

## Fallbacks, health, cooldowns

The router owns cross-target fallback. Every LiteLLM request sends `disable_fallbacks: true`; LiteLLM still handles failover between deployments of the same alias (by `order`, e.g. Groq then Cerebras) and its own cooldowns. Other LiteLLM clients keep the YAML fallbacks.

| Before the first answer token | Result |
|---|---|
| 429 | skip "Rate limited (429)", cooldown 60 s (or `Retry-After`, 5–600 s) |
| read timeout / 408 / 504 | skip "No answer within N s", cooldown 30 s |
| 5xx, 401/403, 404, connect error | skip with the reason, cooldown 15 s |
| not connected (no key) | skipped while deciding, "Not connected: add a key for X in Connections" |

After the first token, a failure ends the reply as `error` with the partial text kept, so nothing is duplicated. Cooldowns are kept in memory, in one router process. A target that is cooling down is retried as a last resort when nothing else is viable, rather than failing a request that has nowhere else to go (e.g. a private request after a local hiccup). **A manual pick never falls back silently.**

## Budget caps (SPEC §13.6) and free-tier accounting

- **`costs.cost_usd`** is what counts toward the caps. Free-tier providers have `free_tier` in `providers.yaml` (Groq, Gemini AI Studio, Cerebras, Ollama, and OpenRouter `:free` models); their calls record **$0**. The LiteLLM or list price goes into the new **`costs.list_price_usd`** column, and the chip shows "Free (≈ $x value)".
- **Per request:** the estimate is input tokens plus 256 output tokens at catalog prices. A candidate over `max_cost_usd` is skipped, and `max_tokens` is capped to what the remaining budget affords.
- **Daily:** today's (UTC) `SUM(cost_usd)` plus the estimate must stay under `daily_cap_usd`.
- When every candidate is blocked by a cap, no model is called. The reply is a **Budget cap reached** card that explains which cap, what was spent, and that free and local models still work.

## Private: never leaves Ollama

- A private candidate must have **every** deployment on a `local` provider. This is checked against the registry, not the alias name.
- Fallbacks are local-only. A cloud pick is skipped with "Private is on: your pick was not used".
- **Threads are sticky-private:** once a thread has a private message, every later request in it stays local, so private history is never sent to the cloud.
- Titles always come from the local model.
- Test proof (`tests/test_chat.py::test_private_provably_stays_local`): every captured LiteLLM call resolves to an `ollama_chat/*` deployment. This holds with a cloud model picked, when the local model returns 500 (the reply errors rather than going to the cloud), and for a later non-private message in the same thread.

## Chat API (router, admin token on every endpoint)

| Endpoint | |
|---|---|
| `POST /chat/send` | SSE turn; `thread_id: null` creates a thread |
| `POST /chat/threads/{id}/regenerate` · `/edit-last` | SSE; replaces the last reply / rewrites the last user message |
| `GET/PATCH/DELETE /chat/threads[/{id}]` | list, read, rename, delete |
| `POST /chat/requests/{id}/stop` | stops a stream (the portal also aborts the fetch) |
| `GET /chat/requests/{id}` | decision log |
| `POST /chat/messages/{id}/feedback` | `up` / `down` / `null` → `model_stats.thumbs_up/down` (toggle-safe) |
| `GET /chat/targets` | picker data: aliases (+ availability reason), connected catalog models by provider |
| `POST /route/dry-run` | the decision without a model call (M3's tester) |

**SSE events.**
- `start`: thread, message and request ids, the provisional title, and whether the thread is private.
- `route`: the candidate being tried.
- `fallback`: the target that was skipped, why, and the next one.
- `thinking`: reasoning text, **streamed but never stored**. It comes from `reasoning_content`, or from `<think>` spans split out of the content even when a tag straddles chunks.
- `delta`: answer text.
- `done`: final content, status and the chip data.
- `notice` (Studio), `blocked` (caps) and `error`.
- `title`: the local title, sent after `done`.

**Logged per request.**
- `requests`: kind, rule, intent, target, the deployment that answered, the catalog id, temperature, autonomy, private, status, latency, time to first token, `fallbacks_tried_json` with reasons, and `decision_json`. Only the **hash** of the prompt is stored.
- `costs`: tokens in/out from the LiteLLM usage chunk, `cost_usd` and `list_price_usd`.
- `model_stats`: one row per task type (the intent), with samples, failures and time-to-first-token p50/p95.
- `messages`: the content, plus the chip data in `meta_json`.

**Titles.** The first words of the message are used immediately. After the first reply, the local model (`ollama/llama3.2:3b`, 20 s timeout) writes a title of 3–6 words. If that fails, the first-words title stays. Rename is always available. qwen3 was tried first: it reasons inside its answer text even with `think: false` or `/no_think`, so titles use llama3.2.

## Portal

- **Thread list:** private threads show a lock.
- **Messages:**
  - Markdown with GFM; raw HTML is never rendered.
  - Highlighted code on the solid panel, with **Copy code**.
  - A collapsible **Thinking… / Thought for N s** line; thinking text appears only live.
  - A live line naming the target being tried and any fallback in progress.
  - Footer: RouteChip → **Why this?** popover, cost, Copy reply, Regenerate, 👍/👎.
  - **Edit** on the last user message; **Stop** while streaming.
- **Composer** (compact on Chat):
  - Target picker: Auto, aliases, then models grouped by provider with the Connections badges. Unavailable targets are disabled with the reason; with Private on, only local targets are allowed.
  - Autonomy Dial, Private switch, temperature (Pro mode).
  - Slash-command hints, keyboard-navigable. Enter sends, Shift+Enter starts a new line.
- **Home:** the composer and the four quick-start chips hand the message to `/chat` through `sessionStorage`, and it is sent on arrival. The chips are now complete sample tasks: a LinkedIn post (writing), failing tests (job hint), an image (Studio notice) and research (job hint).
- **Stream route** `/api/chat/stream`: the Host must be loopback, **Origin** must be this exact loopback origin, `Sec-Fetch-Site` must be same-origin, and the body must be JSON (415 otherwise). Every field is validated again before it reaches the router. `npm run test:bundle` checks all of this, plus foreign Host, foreign Origin and other-port origins.

KB gzip, first-load, budget 200. How it fits:

1. **Lazy chunks:** react-markdown + remark-gfm, highlight.js (core + 13 languages, loaded only when a code block appears), the Why popover, the target picker, rename/delete, and the rare reply states. They load through `next/dynamic` with `lib/lazy-fallback.tsx`: the loading slot shows a caller-supplied stand-in (the static chip, the plain text, the trigger), so nothing flickers.
2. **Strings split by feature.** Turbopack ships a module whole in the shared chunk, so `strings.ts` (7.3 KB gzip) went to every route. Feature text now lives in its own modules next to it: `src/i18n/chat.ts`, `connections.ts`, `wizard.ts`, `dev.ts`, with `tChat`/`tConn`/`tWizard`/`tDev`. `strings.ts` keeps the core text. SPEC §8c now says "every string lives in `src/i18n/`".
3. **The Radix Switch was replaced** by a native `role="switch"` button with the same DOM and `data-state`. That saves about 4 KB on every route with a composer, and the visual baselines are unchanged.

The next big item is Motion's spring engine (7.6 KB, pulled in by the Dial's `useSpring`); see the M3 carry-over.

## Dev-only fault injection

`ROUTER_FAULT_INJECTION=1` lets a chat request carry `fault: {target, kind: "429"|"timeout"}`. It is off by default; compose passes it through as `false` unless you export it for one run. Without it, the API answers 400, and doctor shows yellow while it is on. A 429 is synthesized by the router without calling the provider. A timeout is real: the target gets a 0.05 s read timeout. LiteLLM's own mock parameters are refused unless `dangerously_allow_mock_testing_request_params` is set, which we don't do.

```bash
ROUTER_FAULT_INJECTION=true docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d router
# … try it …
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d router   # back to off
```
